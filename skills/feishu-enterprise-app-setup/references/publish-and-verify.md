# 发布、启用与验收

用户未指定范围时，默认目标是企业内 **所有员工** 可使用文档接入应用；用户明确指定其他范围时按该范围执行和验证。不改变企业全局安全策略，不自动将源文档对互联网公开。

## 发布前

- 已核对目标企业、应用类型和 App ID；复用现有应用时不会误操作同名应用。
- 名称、图标、说明及当前控制台必填项齐备。
- 需要的网页能力已经配置，主页可达；默认回调为 `http://127.0.0.1:4366/oauth/callback`，用户明确指定其他地址时使用其地址。核对项目实际请求，如不一致则说明冲突。
- 默认七项用户权限及应用身份的 `application:application:patch` 已纳入配置；已区分用户身份、应用身份和条件性能力。
- 新版用户授权所请求的 scope 与后台已开 / 将发布的 scope 对齐。
- 新版本中的可用范围符合用户目标（默认所有员工），保存后重新读取确认。不要以测试范围或开发成员列表代替正式可用范围。

## 状态链与判断证据

| 状态 | 需要看到什么 | 可以怎么报告 |
| --- | --- | --- |
| 创建完成 | 目标企业下存在正确类型和名称的应用，取得 App ID。 | 已创建；尚未代表可用。 |
| 配置完成 | 实际权限列表、能力、主页和回调符合本次用途。 | 已配置；仍需完成发布。 |
| 提交发布 | 版本提交成功，平台显示待审核 / 待发布。 | 已提交，待管理员审批。 |
| 正式发布 | 对应版本明确显示已发布 / 已上架等生效状态。 | 已发布，继续核对启用状态与可用范围。 |
| 已启用且范围生效 | 企业应用管理中不是停用，实际有效范围符合用户目标。 | 已启用，并说明已确认的实际范围。 |
| 验证完成 | 非开发者普通员工完成授权，目标接口的小样本调用成功；长期授权场景完成刷新验证。 | 只对已验证的链路报告成功。 |

有免审或自动启用路径时按实际状态走，不人为增加审批步骤。也不能把权限即时生效误当作全员版本已经正式发布。

## CLI 优先，控制台处理必要步骤

优先按 [CLI 流程](lark-cli-create-and-publish.md) 用应用身份配置并提交发布。以下页面操作只用于接口不支持、初始审批或最终状态无法在已获权限范围内读取的步骤，不将全部流程退回手工点击。

## 必要控制台操作路线

1. **开发者后台 → 目标自建应用 → 版本管理与发布 → 创建版本。**
2. 填写未被占用的版本号和变更说明。说明要写清“用于员工本人授权后读取云盘、个人文档库及知识库内容”，不要写成“获取全员所有文档”。
3. 编辑可用范围，选择用户要求的范围（默认所有员工），保存并复核版本详情。
4. 申请线上发布。若需要管理员审批，在本次授权且当前账号具有相应职责时正常审批；否则保留待审状态与申请入口，请有权限的管理员处理。
5. 检查发布结果；再到企业管理后台相应的工作台 / 应用管理页面核对启用状态与实际可用范围。界面名称变化时依据实际页面定位，不按固定坐标盲点。
6. 若平台提示配置变更要重新发版，就发当前变更的版本。不要循环创建重复版本或反复提交同一申请。
7. 已发布但被停用的应用，在用户要求启用的范围内重新启用。已启用则不切换；组织策略限制用户要求的范围时，说明限制，不默默缩小范围。
8. 不操作与本次应用无关的应用，不修改全员工作台布局。普通员工可从实际应用入口访问即可；自动出现在“我的常用”不作为发布条件。

## 普通员工验证

优先使用已有获授权的非开发者测试账号，由本人完成登录授权，不索要其密码或原始 token。

- 普通员工可进入应用，而不是只有创建者 / 测试人员可见。
- OAuth 能回到正确项目；应用与用户身份一致，没有跨企业或跨环境。
- 授权后能读取本人的云盘或指定目录、解析我的文档库并列节点；如包含企业知识库，再验证其已有权限的空间。
- 读取一篇实际返回的文档，并按需要验证一项素材下载。
- 需要 refresh_token 时验证续期；不需要长期授权时标明未纳入本次。
- “所有员工可用”并不替员工完成同意授权，也不让员工读取原本无权访问的文件。

普通员工尚未参与时，仍可完成控制台检查与开发者账号验证，但交付要写明已设置的范围和“普通员工授权验证待完成”，不能宣称普通员工实测通过。

## 常见中断怎么处理

| 现象 | 优先核对 | 处理 |
| --- | --- | --- |
| 找不到企业 / 不能创建 | 当前登录企业、开发者角色及创建权限 | 请用户切换正确企业或由管理员授予必要职责；不另建一个企业规避。 |
| 只有创建者可用 | 正式版本的可用范围、企业侧限制、是否仍在测试版 | 将目标应用范围设为用户要求的范围，并完成平台要求的发布流程。 |
| OAuth 回调错误 | 回调协议、主机、端口、路径、环境和编码 | 修正实际不一致项，保留其他环境配置。 |
| token 缺少 scope | 正确身份页签、已发布权限、OAuth 请求、员工实际同意范围 | 补齐缺项并重新授权；不一次申请所有候选权限。 |
| user token 请求 my_library 失败 | 登录员工与企业、空间详情权限、个人文档库是否已开通、真实 space_id 解析 | 按错误证据定位，不切换管理员身份或当成云盘根目录。 |
| scope 齐全但文档拒绝访问 | 用户本人的文档、目录或素材权限 | 用其有权的样例验证；需要额外授权时明确指出具体资源，不批量公开资料。 |
| 版本一直待审 / 驳回 | 平台审核状态及驳回理由 | 处理可修正项或告知管理员待办；不高频轮询、不假称已启用。 |
| 已发布但员工打不开 | 是否停用、实际范围、主页可达性、企业限制 | 修正目标应用的问题；不是一律加 API 权限。 |
| 本次能用，过期后失败 | 长期授权、refresh_token、有效期与新凭证保存 | 按现行刷新规则修复；不把 access token 成功当成刷新通过。 |

## 交付时用这张表报告实际结果

| 项目 | 实际值或状态 | 证据 / 待办 |
| --- | --- | --- |
| 企业 / 环境 | 本次真实目标 | 当前后台信息 |
| 应用名 / App ID | 可公开的应用标识 | 应用详情 |
| 类型 | 企业自建应用 | 创建或详情页 |
| 正式版本 | 版本号与发布状态 | 版本详情 |
| 启用状态 | 已启用 / 未启用 / 待核实 | 企业应用管理 |
| 可用范围 | 实际范围 / 尚未生效 | 已保存版本及企业侧实际配置 |
| 所需权限 | 最终选定 scope 与身份类型 | 当前权限列表及接口依据 |
| OAuth | 已验证 / 待员工授权 / 失败原因 | 不包含令牌的结果 |
| 云盘 / 我的文档库 / 知识库 | 分别列结果 | 有样例、为空、无权限要区分 |
| 正文 / 素材 / 刷新 | 按本次能力分别列结果 | 不需要的标记未纳入，不伪造成功 |
